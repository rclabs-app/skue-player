# Alternativa HLS recusada com HTTP 405
Data/hora: 2026-11-09 22:01 (America/Recife)
Ferramenta: Codex
Estado: implementação e verificação local concluídas; validação no canal real pendente
Objetivo: preservar o buffer TS e retornar sem espera prolongada quando a alternativa HLS é recusada.
Arquivos em uso: `web/src/components/VideoPlayer.vue`, testes do componente, `web/src/lib/liveStreamUrl.ts`, testes do helper e `docs/ai/CONTEXT.md`.

## Evidência
- O print mostra GET do candidato HLS respondido com HTTP 405. Isso confirma recusa desse endpoint, não indisponibilidade de todo HLS no provedor.
- O código trocava/destruía o TS antes de confirmar a existência do manifesto. O retorno dependia de um erro fatal HLS, sujeito à política de retries/timeouts da biblioteca.
- Alteração planejada: confirmar o manifesto com limite curto antes de trocar o player, mantendo buffer e fonte originais quando a tentativa falhar. Não registrar URLs/credenciais.

## Implementação e resultados
- `probeLiveHlsManifest` faz uma única requisição do candidato, exige resposta HTTP de sucesso e cabeçalho textual `#EXTM3U`, limita a verificação a quatro segundos e cancela a requisição ao fechar/trocar o player.
- HTTP 405 é retornado como candidato recusado; nenhuma instância HLS é criada nesse caso. Não se espera a política de retries do hls.js.
- O player TS só é substituído depois de o candidato passar na verificação. Quando é recusado, o buffer TS permanece disponível. Se esse buffer já acabou durante a espera, a reconexão TS é agendada automaticamente; se ainda houver buffer, aguarda o término.
- Nova mensagem numérica: `[Skue Live] HLS candidate rejected; keeping original TS` com status, sem URL.
- `npm --prefix web run test -- --silent`: 39/39 testes aprovados em 6 arquivos.
- `npm --prefix web run build`: tipagem e build aprovados.
- `git diff --check -- web/src/components/VideoPlayer.vue`: sem erros.
- Testes novos exercitam HTTP 405, corpo HTML com HTTP 200, manifesto com BOM, timeout, cancelamento, preservação do TS e fim do buffer durante a verificação.

## Limites e próximo passo
Não houve acesso ao Firefox nem requisição ao endpoint privado do usuário. O comportamento real após a revisão depende de novo teste no canal. A verificação confirma apenas o formato do manifesto; a reprodução HLS completa continua sujeita à disponibilidade dos segmentos e codecs. Nenhum commit ou deploy foi feito.
